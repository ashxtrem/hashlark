Fold7: check the usable width.

The earlier 840 px split-view frame was not a verified Fold7 viewport. At the 750 dp inner-screen width model, this mock opens details as a separate screen. It does not compress the results and details into two narrow columns.

What is verified, and what is assumed

  • Hardware sizes and resolutions: Samsung specifications.
  • A published physical-device browser measurement reports 750 × 832 screen CSS pixels at DPR 2.625, with a smaller Chrome viewport: Fold7 unfolded measurements and measurement provenance.
  • Android uses density-independent layout units: Android density guidance. At a logical density of 420 dpi, 1968 ÷ (420 ÷ 160) ≈ 750 dp. Physical PPI is not the density setting to substitute here.
  • The native-app examples reserve an illustrative 52 dp vertically for system UI. Actual insets, taskbar, display zoom, text size, and multi-window mode must be measured on the target device.
  • The 360/480 dpi examples are sensitivity tests, not claims about Samsung's factory zoom presets. No physical Fold7 is connected to this workstation.

Assessment: the current mock is usable at the tested Fold7 widths as a list → detail flow. It is not a demonstrated two-pane Fold7 design. With the present 80 dp rail, 52 dp outer gutters, 16 dp gap, and 310 dp detail pane, a 750 dp window would leave about 292 dp for the list even before a browser scrollbar. A simultaneous two-pane Fold7 layout needs a more compact composition and separate validation.
